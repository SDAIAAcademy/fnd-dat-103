What was asked

A checked ingestion script, run live on a batch you have not seen

  • Reads the register in its real encoding and proves it.
  • Converts the vendor log to UTC, the repeated hour included.
  • Checks every session record and the table rules; loads, quarantines or rejects by stated rules.
  • Writes typed Parquet partitioned by day, a quarantine file and a report.
  • Gives the same files when run twice.

Submitted

A public GitHub repository link within two weeks of the workshop: script, schemas, README, a practice run's report. No token, key or .env file.

AI-full for the script: an assistant may have written much of it. In the live run the participant explains every decision the script makes; the questions test that. A script that loads a batch it should have rejected fails the passing rule whatever else it does: the capstone batch must be loaded or rejected for the correct reasons.

In the course: labs 40%, check 20%, script and report 30%, live run 10%. Pass: 70%, with the batch decided for the right reasons.

The rubric scores only the capstone's 40%: the first five criteria are the script and report (75 of 100, the 30%), the last is the live run (25 of 100, the 10%). Labs and the supervised check are scored apart, so nothing is counted twice. Each criterion looks at something the others do not.

Each live run

Six minutes to run and explain, five for questions

6 min · the run

The assessor hands over a batch folder. Run the script on it, open the report, say what it decided and why.

5 min · questions

The assessor asks about one decision, one repair and one rule, from the key in front of them.

2 min · changeover

The next participant shares their screen and opens a terminal.

The assessor generates the batch, not the participant: that is the separation between who builds and who checks. Compare the report with the key: decision, defects, the register's encoding and the vendor log's UTC times. The trainer's reference script, labs/solutions/capstone_ingest.py, matches the key on every seed tried while building the course (seeds 1 to 16, 42, 77 and 100).

Now running

Live run

Questions

Press T to start the first timer. Questions to ask: which rule decided this batch, and where is it written? How did the script know the register's encoding, and what would it do with a third one? Run it again: did any file change? Who receives the quarantine file, and who may release a row from it?

While others run

Write one line for each run

  • The check you will copy into your own script.
  • A decision the script made that you would make differently, and why.
  • One thing the report should tell the data owner that it did not.

Collect the lines in the session's chat; they are feedback, not scores. The rubric score is the assessor's.

After the runs

What eight unseen batches showed

Encodings

Which scripts guessed the register's encoding, and which proved it with the Arabic it must contain?

Time

Did every script place the repeated hour right, or only those that used the sequence?

Decisions

Which rule was hardest to state: the changed field, or the share above which a batch is rejected?

Eight minutes. Compare across the group: this is the first time each kind of batch has been seen by everyone. Thresholds such as 5% are the case organisation's own rules: what matters is that they are written down and applied the same way every time.

What next
